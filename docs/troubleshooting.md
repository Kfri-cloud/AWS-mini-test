# 트러블슈팅 보고서 (최소 1건 필수)

> 실제 리전 접근 문제 진단은 아래 기록에 연결했습니다. EC2/웹 서버 배포의 성공은 [실습 현황](pre-cleanup-evaluation.md)에 별도 정리했습니다. 뒤의 웹 서버 장애 항목은 작성용 템플릿입니다.

## 실제 기록 — 서울 리전 접근 제한 (2026-11-21)

[서울 리전 전환 트러블슈팅 보고서](seoul-region-troubleshooting.md)

- 증상: 기존 프로젝트가 시드니 리전에 할당되어 서울 리전 사용 불가 경고 발생.
- 검증: 시드니 라우팅 화면과 서울 접근 제한 경고 확인, 가입 방식 변경 후 재접속.
- 실제 조치: 사용자 확인에 따라 'Google 신속 가입' 대신 'Google 계정 가입' 방식 사용.
- 결과: 2026-11-21 서울 리전 VPC 대시보드 접근 성공(리전 전환 문제 해결). **이후 별도로** EC2 배포, SSH 접속, 내부 HTTP 200 및 외부 A 방식 브라우저 접속까지 검증 성공.
- 주의: 계정 가입 방식의 차이가 모든 AWS 계정에서 동일한 결과를 만든다고 일반화하지 않음.

### 권장 진단 순서

1. **라우팅:** 퍼블릭 서브넷의 Route Table 연동 및 `0.0.0.0/0 → IGW`, IGW의 VPC 연결 상태
2. **SG:** HTTP 80을 외부에 열었는지, SSH 22는 내 IP/32인지 확인
3. **퍼블릭 IP/DNS:** EC2가 올바른 퍼블릭 IPv4를 가지는지, 주소를 오타 없이 요청했는지 확인
4. **프로세스/로그:** EC2 내부에서 아래 명령을 실행하고 오류 기록 확인

```bash
sudo systemctl status nginx --no-pager
sudo ss -lntp | grep ':80'
curl -i http://localhost/
sudo journalctl -u nginx -n 50 --no-pager
# (외부 PC) curl -i http://<PUBLIC_IP>/
```
