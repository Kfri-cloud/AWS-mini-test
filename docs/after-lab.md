# 실습 후 정리 및 제출

[실습 전 읽기](server-to-aws.md)에서 배운 HTTP 요청 흐름을 자신이 만든 AWS 환경의 증빙으로 설명한다. **서버가 켜져 있을 때 증빙을 확보하고, 리소스를 정리한 뒤 최종 상태를 기록한다.** 아래 빈칸은 직접 실습한 결과로 채운다.

## 1. EC2를 종료하기 전에 증빙 남기기

- **실제 구성**을 [아키텍처 문서](architecture.md)와 [다이어그램](architecture.svg)에 반영한다. VPC, 퍼블릭 서브넷, IGW, 연결된 라우트 테이블, EC2, SG와 외부 요청 흐름을 표시한다. 제출용 그림은 `docs/architecture.png` 또는 `docs/architecture.pdf`로 내보낸다.
- **외부 접속**은 실제로 사용한 방식 하나를 기록한다. A는 EC2 외부 브라우저에서 주소창과 정상 표시된 페이지를 함께 캡처한다. B는 EC2 외부에서 `GET /health`를 보내 요청 주소, HTTP `200`, 설정한 고정 응답 본문을 함께 캡처한다. 증빙 파일은 `docs/evidence/`에 두고 아래 표에 파일 경로와 확인 시각을 적는다.
- **구성·접속 보조 증빙**으로 서브넷에 연결된 라우트 테이블, EC2에 적용된 SG 인바운드 규칙, SSH 접속 및 웹 서버 실행 화면을 남긴다. 공개 저장소에 넣기 전에 개인키, 자격 증명, 계정 정보와 공개할 필요가 없는 IP·로그가 가려졌는지 확인한다.

## 2. 문제와 해결 과정을 기록하기

[트러블슈팅 보고서](troubleshooting.md)에 실제로 겪은 문제를 기록한다. **증상 → 가설 → 확인한 설정이나 로그 → 조치 → 같은 조건에서 다시 확인한 결과**가 이어지도록 작성한다. 문제가 발생하지 않았다면 그 사실을 기록하고, 실제 문제 1건이 필요한 제출 조건은 평가자에게 어떤 실습으로 충족할 수 있는지 확인한다.

## 3. 리소스를 정리하고 결과 기록하기

증빙과 보관할 파일을 확보한 뒤 [정리 체크리스트](cleanup-checklist.md)를 따라 실습용 리소스를 정리한다. EC2, EBS, EIP, IGW, VPC를 실습 리전에서 각각 다시 확인하고 조회 시각과 실제 상태를 기록한다. EIP를 만들지 않았다면 할당 목록을 확인하고 `미생성`으로 기록한다. 비용 대시보드는 집계 지연을 고려해 후속 확인한다.

## 4. 제출 전 대조하기

- [ ] 실제 아키텍처 그림 1장
- [ ] 외부 접속 증빙 1건(A 또는 B)
- [ ] 실제 트러블슈팅 기록
- [ ] 리소스 정리 체크리스트와 최종 상태 증빙

[평가 기준 1~4](evaluation-criteria.md)에서 실습 결과와 설명해야 할 항목을 확인한다. GitHub에 올린 뒤 README에서 제출 자료와 증빙 링크가 열리는지 확인한다.
