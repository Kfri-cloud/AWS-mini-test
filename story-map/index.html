내 PC에서 열리는 웹페이지

브라우저와 서버가 같은 컴퓨터에 있는 상황부터 시작한다.

  1. 내 브라우저GET /
  2. 127.0.0.1:8000내 PC 안에서 연결
  3. Python 웹 서버200 OK + index.html 반환

세 지점이 모두 같은 PC 안에 있다. PC는 실행 환경이고 Python 웹 서버는 요청을 처리하는 프로그램이다.

다른 사람이 이 주소를 입력하면?

그 사람의 브라우저는 그 사람의 PC에 접속한다. 127.0.0.1은 언제나 요청을 보내는 컴퓨터 자신을 가리킨다.

  3. 보안 그룹EC2 네트워크 인터페이스에서 TCP 80 허용 여부 판단

VPC 안의 배치

VPC 10.10.0.0/16 안에 퍼블릭 서브넷 10.10.1.0/24와 EC2 10.10.1.10이 있다. 서브넷에 연결한 라우트 테이블의 0.0.0.0/0 → IGW가 인터넷 방향의 기본 경로를 지정한다.

주소 변환, 경로 선택, 허용 규칙의 차이

IGW는 EC2의 퍼블릭 IPv4와 사설 IPv4를 대응시킨다. 라우트 테이블은 목적지별 경로를 정한다. 보안 그룹은 허용할 연결을 정한다. 표나 규칙을 물리 장비처럼 거친다는 뜻은 아니다.

01 · 실습 전

브라우저가 요청하면 서버가 응답한다

내 노트북도 웹 서버를 실행할 수 있다. 브라우저는 요청을 보내는 클라이언트, 요청을 받아 답하는 프로그램은 웹 서버다. 이 두 프로그램은 같은 컴퓨터 안에서도 통신할 수 있다.

서버의 역할요청과 응답로컬 실습오류 구분

서버라고 부르는 두 가지

서버 컴퓨터

운영체제와 프로그램이 돌아가는 곳이다. 내 PC도 서버 역할을 맡을 수 있고, AWS에서는 Linux가 실행되는 EC2 인스턴스가 이 역할을 맡는다.

웹 서버 프로그램

Nginx나 실습용 Python 서버처럼, 운영체제 위에서 실행되어 주소와 포트에 연결을 받고 HTTP 요청을 처리한다. 프로그램을 꺼도 컴퓨터 자체는 계속 켜져 있을 수 있다.

정적 페이지는 준비된 HTML이나 이미지 파일을 돌려준다. 동적 페이지는 로그인 상태나 검색어에 따라 애플리케이션이 응답을 만든다. Nginx는 파일을 직접 반환하거나 요청을 애플리케이션으로 전달할 수 있다. 이번 실습은 파일 하나로 시작한다.

주소창에 URL을 입력하면 일어나는 일

http://127.0.0.1:8000/을 예로 들면 http는 통신 규칙, 127.0.0.1은 자기 컴퓨터의 주소, 8000은 접속할 포트, /는 요청 경로다.

  1. 서버 주소 찾기도메인 이름을 쓰면 브라우저는 DNS 등으로 IP를 찾는다. 이 예시는 IP를 직접 입력한다.
  2. 포트에 연결하기이 HTTP/1.1 예에서는 TCP로 연결한다. 웹 서버는 해당 주소와 포트에서 연결을 기다려야 한다. HTTPS에서는 TLS로 통신을 보호한다.
  3. HTTP 요청 보내기브라우저는 GET /를 보내 페이지를 요청한다. 헤더에는 접속 대상 등을 담을 수 있다.
  4. 응답 읽기서버는 결과를 알리는 상태 코드, 본문의 형식 등을 담은 헤더, 필요한 경우 본문을 보낸다. 브라우저는 HTML을 화면에 그린다.

요청 예시

GET / HTTP/1.1
Host: 127.0.0.1:8000

GET은 가져오겠다는 메서드이고, /는 서버가 처리할 경로다.

응답 예시

HTTP/1.0 200 OK
Content-Type: text/html

<h1>Hello, web server!</h1>

200은 처리 성공을, Content-Type은 본문의 형식을 나타낸다. Python 로컬 서버가 보낼 수 있는 응답을 단순화했다.

내 PC에서 HTTP 응답 확인하기

  1. 빈 실습 폴더에 index.html을 만들고 아래 내용을 저장한다.
    <!doctype html>
<meta charset="utf-8">
<h1>Hello, web server!</h1>
  2. 그 폴더에서 Python 3로 서버를 실행한다. --bind 127.0.0.1은 자기 PC에서 들어오는 연결만 받게 한다.
    python -m http.server 8000 --bind 127.0.0.1

    환경에 따라 python3 또는 Windows의 py를 쓴다.

  3. 서버 터미널은 열어 둔 채 새 터미널에서 아래 요청을 보낸다. Windows PowerShell에서는 curl.exe를 쓴다.
    curl -i http://127.0.0.1:8000/
curl -i http://127.0.0.1:8000/missing.html

    첫 요청의 200과 HTML, 둘째 요청의 404를 응답 첫 줄과 서버 로그에서 비교한다. 확인 후 서버 터미널에서 Ctrl+C로 종료한다.

응답이 없을 때와 오류 응답이 올 때

먼저 관찰한 증상을 고르고, 어느 지점까지 요청이 갔는지 판단한다.

연결이 거부되거나 시간이 초과됐다

HTTP 상태 코드를 받기 전 단계다. 연결 거부라면 주소와 포트, 서버가 그 주소에서 대기 중인지 확인한다. 시간 초과라면 경로와 필터링부터 살펴보고, 연결 뒤 응답을 기다리다 멈춘 경우에는 서버 로그도 본다. 증상만으로 원인을 확정할 수는 없다.

404 Not Found가 돌아왔다

어떤 웹 서버가 HTTP 응답을 보냈으므로, 먼저 응답한 서버가 기대한 서버인지 확인한다. 그다음 URL의 경로, 실제 파일 이름, 웹 루트 또는 Nginx 경로 설정을 확인한다.

500이나 502가 돌아왔다

500은 서버가 요청 처리 중 문제를 만났음을 뜻한다. 502는 게이트웨이나 프록시가 뒤쪽 서버에서 유효한 응답을 받지 못했음을 뜻한다. 해당 시각의 웹 서버 오류 로그와 연결된 애플리케이션 상태를 확인한다.

AWS에서 확인할 것 · EC2에 SSH로 접속한 뒤의 127.0.0.1은 EC2 자신이다. 그 요청이 성공하면 웹 서버의 내부 응답을 확인한 것이다. 다른 사람도 볼 수 있는지는 별도 PC에서 EC2의 퍼블릭 IP로 요청해 확인한다. AWS 요청 경로 보기 ↓

02 · AWS 실습

같은 페이지를 인터넷에 공개하기

EC2에서 Nginx를 실행하고, 외부 브라우저가 찾을 주소와 서버까지 이어지는 경로를 설정한다. 퍼블릭 서브넷의 라우팅, 퍼블릭 IPv4, 보안 그룹, 웹 서버 리스닝 상태를 함께 확인한다.

로컬에서 열던 웹페이지를 AWS에 올리면

두 환경 모두 브라우저가 GET /을 보내고 웹 서버가 HTML을 반환한다. 아래 도식은 같은 요청이 각 환경에서 어느 주소와 포트로 연결되는지 비교한다.

외부 요청이 AWS 안에서 지나가는 경로

  1. 퍼블릭 IP로 접속브라우저가 EC2의 퍼블릭 IPv4에 TCP 80으로 연결한다.
  2. IGW가 VPC로 연결인터넷 게이트웨이가 퍼블릭 IPv4를 EC2의 사설 IPv4에 매핑한다.
  3. SG가 연결을 검사인바운드 규칙이 접속자의 TCP 80 연결을 허용하면 요청이 Nginx에 도달할 수 있다.
  4. Nginx가 응답Nginx가 GET /에 HTML을 반환한다. 외부 목적지로 가는 응답은 서브넷의 IGW 경로를 사용한다.

SSH는 관리자가 EC2를 설정할 때 쓰는 별도 연결이다. 관리자 IP에서 TCP 22로 접속하며, 방문자의 웹 요청 경로에는 포함되지 않는다. AWS 인터넷 게이트웨이 공식 문서 ↗
